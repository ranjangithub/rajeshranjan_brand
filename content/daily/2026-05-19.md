### 9. AWS + Cisco AI Defense — Securing MCP and A2A Agent Deployments at Enterprise Scale

**Governance Alert** · AWS Machine Learning Blog

Three core enterprise AI agent security challenges identified: visibility gaps (you can't monitor what agents are doing), security bottlenecks (current tools weren't designed for agent traffic), and compliance risks (agent actions aren't captured in audit trails). Recommended pattern: add Cisco AI Defense as a security proxy between agents and every tool they access.

**Why it matters:** MCP and A2A are becoming de-facto protocols for agent-to-tool and agent-to-agent communication. Without MCP-specific security controls, you have an AI agent with unmonitored access to your production systems. This is one of the first enterprise architectures that explicitly connects agent-level observability to compliance requirements (NIST AI RMF).

> **Rajesh's take:** MCP deployments without a security proxy layer are architecturally incomplete. The pattern is clear: agent → MCP security proxy → tool/system. Every production MCP deployment needs request/response logging, rate limiting, policy-based tool call authorization, and anomaly detection on call patterns. This is the WAF pattern for agents. If you're deploying Claude Code, GitHub Copilot, or custom agents via MCP, read this post before you deploy.

## 🔬 Research Worth Reading

**1. STRIDE-AI: A Threat Modeling Framework for Generative AI Security Assessment**
- **Link:** arxiv.org/abs/2605.17163
- **Main idea:** Extends the classic STRIDE threat modeling framework to cover generative AI-specific threats: prompt injection as Spoofing, data leakage as Information Disclosure, hallucination-induced errors as Tampering.
- **Why it matters:** STRIDE is a language enterprise security architects already speak. Translating AI-specific threats into STRIDE vocabulary lowers the barrier to AI security risk assessments.
- **Practical implication:** Enterprise security teams can now run STRIDE threat models on AI components using familiar notation. Immediately useful in design reviews.
- **Verdict:** Immediately useful — a vocabulary bridge between traditional security and AI security.

**2. ADR: An Agentic Detection System for Enterprise Agentic AI Security**
- **Link:** arxiv.org/abs/2605.17380
- **Main idea:** Runtime detection for agentic AI behavior — identifying when an agent operates outside authorized scope, is being manipulated by prompt injection, or takes actions inconsistent with its assigned task. Behavioral fingerprinting across tool call sequences.
- **Why it matters:** Closer to SIEM anomaly detection than input filtering — focuses on behavioral patterns, not just inputs/outputs.
- **Verdict:** Academic with a clear implementation path for teams running LangChain or similar agent frameworks.

**3. ContraFix: Agentic Vulnerability Repair via Differential Runtime Evidence**
- **Link:** arxiv.org/abs/2605.17450
- **Main idea:** AI agent that fixes code vulnerabilities by differentially analyzing runtime behavior before and after a patch — not just static code analysis.
- **Why it matters:** Catches behavioral vulnerabilities (race conditions, memory leaks, privilege escalation) that static analysis misses consistently.
- **Verdict:** 12–24 month horizon. Early signal for where AI-assisted AppSec is heading.

**4. BLAgent: Agentic RAG for File-Level Bug Localization**
- **Link:** arxiv.org/abs/2605.17965
- **Main idea:** Uses agentic RAG to locate the specific file(s) responsible for a reported bug across a large codebase, reducing the search space before debugging begins.
- **Practical implication:** Could automatically annotate bug reports with probable file locations before a developer opens them.
- **Verdict:** Immediately useful for large-codebase teams. Low implementation complexity.

**5. From Craft to Kernel: A Governance-First Execution Architecture for Agentic Computers**
- **Link:** arxiv.org/abs/2604.18652
- **Main idea:** Governance policies enforced at the kernel level, not the application layer. A Semantic ISA where agent instructions carry intent metadata. Harder to bypass than application-layer guardrails.
- **Verdict:** Mostly academic — 3–5 year horizon. Foundational for regulated AI systems in defense, healthcare, and financial services.
